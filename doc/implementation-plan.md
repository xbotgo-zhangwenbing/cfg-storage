# 分批实现计划

业务范围只包含图像设置的四个字段：规格、编码、白平衡锁定、防频闪。暂不加入相机、同步开关、篮球或其他模块。按批次恢复已经讨论的底层架构，不提前混入后续功能。

## 第一批：配置管理前端（已完成）

- Qt 窗口仅保留配置列表、新建、重命名按钮和当前配置名称。
- Service 的 Impl 持有内存 IndexState，使用 UUID 标识配置；负责名称去空白、1–20 个用户可见字符、名称唯一性、50 个配置上限及目标 ID 校验。
- 新建后自动选中新配置；单击列表只选中，双击配置条目才提交切换。
- Worker 接收明确的新建、重命名和切换命令，在标准 C++ IO 线程执行空实现；调用方等待完成后才更新内存索引。
- 本批不读写文件；退出后内存列表不保留。此前临时版本的 load、flush、queueSave 已移除，后续按新架构实现。
- 已通过完整编译和 Qt offscreen 交互验证：新建、重命名、选择与切换分离、重复名称/无效输入拒绝、关闭和重新初始化，以及无文件写入。

## 第二批：图像业务内存（已完成）

- ImageParametersConfigImpl 独占四字段 ImageParametersData，通过 shared_mutex 保护；Service 只持有模块，不复制业务状态。
- 公共 IImageParametersConfig 提供 getAll/setAll 和四个字段的独立 getter/setter，不含相机、同步、回调或 IO 依赖。
- 整体修改先校验全部字段，非法枚举拒绝且不改变原数据；字段修改在写锁内只更新目标字段。
- UI 左侧为配置列表和管理按钮，右侧为四个图像编辑控件及独立的只读文本框。修改控件仅调用 setter，不自动重新读取；仅点击“读取内存”时通过 getAll 更新文本快照，不回填编辑控件。文本保留上次读取结果，直到再次读取；新建或切换时清空旧文本。编辑控件仅在初始化及修改失败恢复时读取内存并阻断信号。
- 初始化使用默认值：1080p30、H.264、白平衡锁定、防频闪自动。关闭后 getter 保留最后值，setter 拒绝；重新初始化恢复默认值，模块地址保持稳定。
- 本批未接入 Codec 和 Worker 保存接口，没有文件 IO；新建/切换仍仅更新第一批内存索引，不负责图像数据隔离或恢复，第四批完成。
- 完整编译、第一批交互回归、第二批 Qt offscreen 交互、非法值拒绝、快照副本、并发字段修改、整体快照一致性及关闭/重启验证均通过。

## 第三批：内存提交 IO（已完成）

- 图像模块直接持有 Worker 引用。setter 在模块写锁内生成完整 JSON 快照，成功入队后才提交业务内存修改；失败保持原值。
- Service 和模块共用配置读写门锁：管理操作持独占锁，模块 get/set 持共享锁，再取得模块锁；IO 线程不反向访问业务对象，避免切换与 setter 写错配置目录。
- Worker 按 configId/moduleKey 合并任务，入队时分配全局自增 revision，移动所有权自动释放被替换的 JSON。
- 启动时通过模块存储描述表指定 MainConfig 或 SeparateFile，图像模块默认 MainConfig；模块业务代码只提交 key 和快照，不参与路径选择。
- IO 线程独占完整主配置 JSON、独立文件缓存、各文件 dirty 和保存截止时间。更新只替换模块节点，不重新读盘；首次修改后一秒保存，新修改不重置期限，无任务时条件变量睡眠。
- 默认文件写入 configurations/v4/<config-id>/config.json，包含 config_id 和 image_parameters 四字段节点。SeparateFile 模式写入 <模块 key>.json，主配置对应节点只保存 storage=file、path=<模块 key>.json；后续只更新独立内容时不重复写主配置。两种模式均使用 tmp/bak 安全保存。
- 新建、重命名和切换命令先处理此前快照并同步保存；切换暂时只调整后续写入目标，不读取目标文件、不重置业务内存。新建默认文件和真正的加载/激活仍属于第四批。
- 每个文件保存成功后单独清除 dirty，失败文件保留快照并一秒后重试；所有相关文件成功后 savedRevision 才推进，部分文件成功不能掩盖其他文件失败，错误可查询。关闭排空队列并尝试最终保存；失败时报告错误并保留 Worker 缓存，可以对同一根目录重新启动重试。
- Demo 底部显示已接收修改版本、已保存版本及错误，状态定时查询不读取业务数据，不改变手动“读取内存”的文本快照。
- 删除 src/basketball、IBasketballConfig，以及不参与构建但仍引用篮球模块的旧 ServiceImpl 和 Repository/路径实现；src/include/demo 中无篮球代码引用。
- 新增 CTest 保存流程检查，覆盖延时/连续修改、并发字段、完整主配置多模块合并、主配置与独立文件混合保存、文件引用、独立文件单独更新、部分失败和重试、保存屏障、退出保存及入队拒绝时内存不变。完整编译、CTest 和 Qt offscreen 界面验证均通过（手动读取结果不自动刷新、单击只选中、双击切换、两个配置分别写入）。

## 第四批：新建、加载和切换（已完成）

- Worker 的 createConfiguration 接收各模块默认快照，在 IO 线程按存储描述生成完整主配置和独立文件；先写临时目录，全部成功后重命名提交。已有目标目录不覆盖，失败不展示半份新配置。
- loadConfiguration 在 IO 线程建立候选缓存，校验配置 ID、模块对象和独立文件引用，支持 JSON 读取失败时尝试 .bak；返回的主配置和独立模块都是独立 JSON 副本。
- Service 通过 Codec 校验四个图像字段，失败时丢弃候选，不改变当前模块内存或索引。全部成功后调用 activateConfiguration，再一次替换模块 ID、图像数据和当前配置 ID。
- 候选使用令牌标识，最近一次加载失败、主动丢弃、重复激活或期间出现新的业务修改时，不允许使用旧候选激活。
- 加载前先保存当前待写修改；新建使用四字段默认值，切换恢复目标文件值。加载和激活不会再次编码、入队或把缓存标记为 dirty，后续保存保留完整主配置中的未知节点。
- UI 双击切换成功后刷新四个编辑控件，新建后显示默认值；读取文本只在点击“读取内存”后显示，参数修改仍不自动更新文本。
- 增加“重新加载”按钮：先保存待写修改，再读盘、校验、激活当前配置。成功后刷新控件并清空旧读取文本，不隐式丢弃未保存修改。
- 退出继续关闭写入口、排空保存队列并完成最终保存，失败时显示错误；启动创建默认文件失败时也显示错误。
- 完整编译、CTest 和 Qt offscreen 界面验证覆盖：默认文件创建、两份配置独立恢复、失败切换不改变状态、重载保存屏障、候选与业务副本隔离、主/独立文件读取、备份恢复、未知节点保留、回填不触发 setter、读取文本手动更新。
- 当前索引和重命名仍仅在内存中。重启暂时创建新的“未命名”配置，不恢复已有配置列表；此项属于第五批，不在第四批提前扫描或自行补索引。

## 第五批：索引持久化和恢复（已完成）

- Service 的 Impl 持有内部 IndexState，条目使用可扩展的 ConfigurationEntry 结构体和 vector。IndexCodec 仅转换和校验 JSON、版本、名称、ID 和数量；Worker 独占索引 JSON 缓存与全部文件 IO。
- 根目录保存 index.json，记录 index_schema_version=1、configuration_version=4、current_config_id 和配置 ID 到元数据对象的映射。实际配置位于 configurations/v4/<config-id>/。
- 初始化按主 index、index.json.bak、当前版本目录扫描的顺序恢复。主索引版本不兼容时直接失败，不能用旧备份绕过版本保护。扫描恢复 ID 并生成唯一默认名称，忽略临时目录及未来版本目录。
- 当前配置不可加载时尝试索引中的其他配置；没有可用项且未达数量上限时创建新的默认配置。坏目录保留，不自动删除用户数据。
- 激活候选前先保存下一份完整索引；成功后才提交 IO 缓存、模块内存和 Service 索引。切换或重命名写索引失败，原名称、当前 ID 和写入目标不变。
- 新建文件成功但索引提交失败时，Worker 清理本次新建且未被索引引用的目录；Service 不添加失败条目。不能使用该清理接口删除已有配置。
- 重命名持久化到索引，保留 UUID 和目录名。索引顶层及配置条目的未知元数据在更新时保留。
- 从备份恢复后重写主索引时不将损坏主文件覆盖到有效 .bak；正常保存保留 tmp/bak 机制。已知索引完全不变时不重复写入。
- 重启恢复当前配置、列表、名称和四个参数，不再每次创建新 UUID。UI 保持双击切换和手动读取文本的交互。
- 当前支持索引格式 1 和配置布局 v4。旧布局尚无数据转换定义，不编造迁移规则：遇到旧版本或更高版本会报错并保留原文件；完整跨版本转换按设计文档后续添加。
- CTest 增加持久化重启、未知元数据保留、索引写失败回滚、失败新建清理、备份/扫描恢复、无效当前项回退、版本保护、启动写失败重试和 50 项上限验证。完整编译、CTest、Qt offscreen 重启验证均通过；界面重启后恢复列表、重命名结果、所选配置和参数，初始读取文本为空且不触发 setter。

每批完成独立验证并记录结果；五批已完成。当前最小实现只包含四个图像参数；其他模块、历史布局迁移、配置另存/导入等完整产品功能不属于本轮实现。

## 整份配置变更信号（已接入）

- IImageParametersConfig 增加 Qt changed(ImageParametersData) 信号，参数为完整业务数据快照，并声明/注册元类型供跨线程连接使用。
- 只有整份配置的替换会通知，包括初始化恢复、新建、切换和重载。普通 setAll/单字段 setter、重命名、自动落盘、失败的配置操作均不触发。
- 模块替换后在锁内按顺序投递通知，在对象所属 Qt 线程中实际发出信号，避免持锁执行用户槽；本项目初始化模块在应用主线程进行。
- Demo 通过信号参数刷新编辑控件和列表，不在新建/切换/重载按钮中重复读取。手动文本在配置替换时清空，只有点击“读取内存”才显示；普通 setter 不更新文本。
- 配置门锁和模块锁继续使用统一的层次顺序，不使用 std::lock 混合原有 Service 的门锁流程。
- 已通过编译、CTest 及 Qt offscreen 界面验证：整份配置成功替换通知一次，普通 setter/重命名/失败操作不通知；槽可查询模块和 Service，后台线程重载及 QueuedConnection 可正确收到数据；界面可仅监听信号响应外部配置操作。

## 配置列表与创建时间

- Demo 的 refresh 重命名为 refreshConfigurationList，明确只刷新列表、当前配置名称和按钮状态。
- ConfigurationSummary 和内部 ConfigurationEntry 增加 createdAt，使用 UTC ISO 8601 字符串，索引字段为 created_at。新建时生成一次，重命名、切换、内容保存、重启均保留。
- 老索引缺少创建时间时保持为空；目录扫描无法恢复原始时间，不使用恢复时刻冒充创建时刻。列表 tooltip 显示本地时间或“未知”。

## 删除配置

- Service 拒绝删除当前配置、最后一个配置和不存在的 ID。
- Worker 先保存移除条目后的 index，再删除 `configurations/v4/<config-id>/` 目录；Service 只有在两步成功后才移除内存索引。
- Demo 配置列表增加删除按钮和确认弹窗，删除成功后由配置列表刷新逻辑更新界面。
