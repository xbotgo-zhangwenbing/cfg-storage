1. index.json 中有verson版本， 然后代码中也有一个版本，代码中的版本决定是决定读取configurations 下面的v1, 还是v2, 如果首次加载时候，代码中是v2, 而configurations 有更低的版本，那么就需要将最近的那个版本升级到当前版本来。升级的逻辑我没有想好，这里的升级可能不是字段的新增或者是删除，有可能是某个key 的结构体变了这种，这样我们是不是要有一个回调函数，比如v1 升级到v2 v2 升级到v3 这种，反正中间可能隔着版本，比如之前是bool 值，现在变成了int, 那么升级之后要把之前的bool 值对应到当前的0,1 这样。升级完了以后就把之前的删除。比如从v1->v2 成功后, 那么直接删除v1。由于每个版本可能都有变化，是要定义升级函数吗，这个升级函数应该是将来书写的。现在需要搭建这个框架。

## 存储架构
1. 需要整体的配置分模块，来存储，分类。宗旨就是内存中存一份数据。每一个模块都可以进行get set ，都是使用锁来锁住，多线程并发访问。class XBotGoConfigService final : public QObject 这个类用来管理这些模块，这个类可以是单例的，返回的都是每个分模块配置的引用或者指针，我认为指针是好的，或者是共享指针。这个到时候评估一下。
2. 还有同步到文件的模块，这部分就是将刚刚set 之后需要拷贝一份到io 队列，然后io 队列可以根据当前配置文件的模块去更新对应的io 线程中的配置，这份配置和内存中一致，就是把内存中设置的刷过来，唯一的区别就是，假如io 队列中有一百个，那么我们在循环点那一刻，需要将这一百份的副本合并到io 线程中这一份配置，然后调用obs_data_save_json_pretty_safe 刷新到文件中。这里我的想法是，比如队列中有10 A 类型的配置，我们刷一遍循环的时候，我们是不需要从a0 合并过去的我们直接使用最新的，反正就是替换，我的想法是不是队列中有的，同一类的使用最新的。还是怎么，反正这里我的想法是尽可能的省内存。不要用户修改了一百次，队列中存了一百个副本等着消耗。这里的同步动作就是用户调用set 之后需要抛到io 线程来刷新
3. 首次启动加载，还有中途切换配置文件。 1，2 这两个内存，io 队列中的数据都需要刷新，这里需要做计划，首次加载还好，中途切换我还没有想好。
